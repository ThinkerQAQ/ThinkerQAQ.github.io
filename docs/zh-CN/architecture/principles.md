# 架构原则

**极简核心、可插拔、配置化、自举，成熟组件优先复用。**

## 如何决策

开发新能力前，依次检查：

1. 是否已有合适的标准协议？
2. 是否有维护良好的 SDK、开源库或托管服务？
3. 是否可以通过现有配置与 Provider 解决？
4. 是否可以放到项目扩展层？
5. 以上路径都不能满足需求时，才考虑自研核心机制。

## 应用到博客

- **核心职责清晰**：内容仓库存原文，博客引擎负责渲染与静态构建。
- **集成可替换**：发布平台、图表渲染、搜索引擎和托管平台尽量通过既有接口接入。
- **配置优先**：DevTool 使用 `.devtool.toml`，BlogCTL 使用 `blogctl.toml`，运行环境的敏感信息放在 Secrets 中。
- **自举**：DevTool 管理项目的正式验证、构建和打包能力；博客引擎可以使用 fixtures 在本地独立运行。

例如，新增一个发布平台时，优先在现有 Adapter 接口上接入成熟 SDK，复用编译、图片处理和任务记录。只有确认现有组件确实不能满足需求，才实现新的底层能力。
