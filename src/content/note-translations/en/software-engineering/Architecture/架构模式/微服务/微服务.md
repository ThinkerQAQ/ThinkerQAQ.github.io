Microservices split a system into independently deployable services aligned with business/ownership boundaries. Each service should own its behavior and usually its data boundary rather than sharing a database as an undocumented integration API.

Benefits can include independent deployment/scaling/ownership and fault containment. Costs include network failures, latency, distributed consistency, observability, compatibility, duplicated platform work, and operational complexity.

Do not split by technical layer or number of tables. Start from bounded ownership/change patterns and choose microservices only when the independence is worth the coordination cost.
