## 1. What Is a System Call?

A system call is the controlled interface through which user-space code requests a privileged kernel service.

Examples include operations for:

- files and directories;
- sockets;
- process/thread management;
- memory mappings;
- timers and synchronization.

## 2. System Call vs. Function Call

An ordinary function call stays within the current privilege domain and follows the language/platform calling convention.

A system call transitions into the kernel through an architecture-defined mechanism, identifies a syscall operation, passes arguments in ABI-defined registers/memory, and later returns to user mode.

On x86-64 Linux, direct syscall argument registers differ from the ordinary System V function-call ABI in details such as the fourth argument register. These details are architecture-specific and should not be treated as a universal syscall model.

## 3. Library Wrappers

Applications often call libc or language-runtime functions rather than issuing raw syscalls directly.

A wrapper may:

- translate errors into library conventions;
- restart interrupted calls;
- select a newer syscall variant;
- avoid a syscall entirely through caching or vDSO support.

Therefore, "calling a function with an OS-looking name" does not guarantee a kernel transition occurred.

## 4. Cost

A syscall is more expensive than a trivial in-process function call because it crosses the user/kernel boundary and executes kernel logic. However, real performance depends much more on the work performed—blocking, copying, page faults, storage, networking—than on the transition cost alone.
