## 1. What Is Partitioning?

Partitioning splits a dataset into multiple subsets and stores different subsets on different nodes.

A common design has two mapping layers:

1. derive a partition key from each record and map `key → partition`;
2. assign each partition to a machine or node: `partition → node`.

## 2. Why Partition Data?

- a dataset may be too large for one machine;
- read and write traffic can be spread across multiple nodes;
- storage and compute capacity can scale horizontally.

Partitioning also introduces routing, rebalancing, hot-partition, and cross-partition-query problems.

## 3. Partitioning vs. Replication

Partitioning and replication solve different problems and are commonly used together.

| | Partitioning | Replication |
| --- | --- | --- |
| Core idea | Split one dataset into different subsets | Keep redundant copies of the same data |
| Main scaling benefit | Storage and read/write throughput | Read scale and availability |
| Common property | Data lives on multiple nodes | Data lives on multiple nodes |

A production system often partitions data and then keeps multiple replicas of each partition.
