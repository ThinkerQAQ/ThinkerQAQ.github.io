Tomcat tuning starts with workload/SLO measurement, not a copied list of `server.xml` numbers.

Key capacity controls include connection limits, request-processing concurrency, accept/backlog/queue behavior, timeouts, keep-alive, TLS cost, request/body limits, and JVM/container CPU/memory.

Increasing worker threads cannot fix a saturated database or downstream service; it can increase queueing and contention. Align request concurrency with downstream connection pools and service capacity.

Measure p50/p95/p99 latency, active/queued requests, thread states, CPU, GC, connection counts, and downstream timings before and after changes.
