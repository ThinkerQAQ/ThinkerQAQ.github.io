Tomcat startup can be understood as construction/configuration of a component graph followed by lifecycle initialization/start.

At a high level, bootstrap creates the server runtime; services connect one or more network connectors to a container engine; host/context/webapp components are prepared; connectors begin accepting traffic after required components start.

Tomcat's exact classes/method sequence changes across releases. The durable model is **hierarchical components + lifecycle transitions + connector/container separation**, not one historical source-code call stack.
