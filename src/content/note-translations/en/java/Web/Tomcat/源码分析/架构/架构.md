Tomcat can be reasoned about through a few boundaries:

- **Server/Service** organize runtime services;
- **Connector** handles network/protocol input;
- **Engine/Host/Context/Wrapper** route/process requests through the web-container hierarchy;
- lifecycle abstractions coordinate component startup/shutdown;
- executors/event loops/threads perform the actual work according to connector configuration.

This architecture is more durable than one release's class diagram. Version-specific source reading should be anchored to the exact Tomcat tag being inspected.
