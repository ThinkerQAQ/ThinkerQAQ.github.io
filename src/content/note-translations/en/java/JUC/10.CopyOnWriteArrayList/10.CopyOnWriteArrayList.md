## 1. What It Is

`CopyOnWriteArrayList` is a thread-safe list optimized for workloads with **many reads and relatively few writes**.

Readers access a published array snapshot without taking the writer lock. A mutating operation acquires a lock, copies the current array, modifies the copy, and then publishes the new array.

## 2. Why Reads Are Cheap

A read such as `get(index)` works against the current array reference. Because writers never mutate that published array in place, readers can safely continue using the old snapshot while a writer prepares a new one.

This gives readers stable snapshot semantics without blocking on ordinary writes.

## 3. Write Cost

The trade-off is substantial:

- each structural write copies the backing array;
- large lists make writes expensive in CPU and allocation;
- frequent writes create GC pressure;
- concurrent writers are serialized by the internal write lock.

Therefore it is a poor general-purpose replacement for `ArrayList` plus synchronization.

## 4. Iterator Semantics

Iterators are **snapshot iterators**. They observe the array that existed when the iterator was created and do not reflect later modifications.

They do not throw `ConcurrentModificationException` merely because another thread updates the list, but iterator mutation operations are unsupported.

## 5. Good Use Cases

Typical examples include listener registries, routing/configuration snapshots, or other collections that are read frequently and changed rarely.

If writes are common or the collection is large, consider a different concurrent data structure or explicit synchronization strategy.
