## 1. Purpose

`ThreadLocal<T>` associates a value with the current thread rather than sharing one mutable value across threads.

Common uses include request/thread context or non-thread-safe per-thread helpers.

## 2. Storage

Values are effectively stored in a map associated with the `Thread`, keyed by `ThreadLocal` identities.

Historical implementation discussions refer to weak references for keys. A key can be collected while its value remains reachable from a long-lived thread until stale entries are cleaned.

## 3. Thread Pools and Leaks

Pool threads live far longer than one task. If a task sets a large/thread-specific value and fails to remove it, later tasks can inherit stale context or keep memory alive.

Pattern:

```java
try {
    local.set(value);
    doWork();
} finally {
    local.remove();
}
```

## 4. Not Automatic Async Context Propagation

ThreadLocal context does not automatically follow work submitted to another thread, `CompletableFuture`, reactive pipeline, or virtual-thread/task abstraction.

Use explicit context propagation or framework-supported scoped/context mechanisms where appropriate.

## 5. Prefer Explicit Parameters for Business Data

Thread-local state is convenient infrastructure plumbing but can hide dependencies. Pass business state explicitly when feasible.
