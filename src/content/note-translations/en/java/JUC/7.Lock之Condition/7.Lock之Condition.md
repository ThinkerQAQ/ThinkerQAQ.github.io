## 1. What Is `Condition`?

A `Condition` associated with a `Lock` lets threads wait until some shared-state predicate may have changed.

It is analogous to `Object.wait/notify`, but one lock can create multiple condition queues for different predicates.

## 2. Standard Pattern

```java
lock.lock();
try {
    while (!predicate()) {
        condition.await();
    }
    // state is now usable
} finally {
    lock.unlock();
}
```

Always check the predicate in a `while` loop because wakeups can be spurious or another thread may consume the condition before this thread reacquires the lock.

## 3. `await`

`await()` atomically releases the associated lock and suspends the thread. Before returning, it reacquires the lock.

## 4. `signal` / `signalAll`

These move/wake waiting threads so they can compete to reacquire the lock. Signaling does not transfer the lock immediately; the signaling thread still owns it until unlock.

## 5. AQS Model

AQS-based conditions maintain a condition-wait structure distinct from the synchronizer acquisition queue. Signaled waiters transition back toward lock acquisition.

Exact node mechanics are JDK-version-specific; the lock/predicate semantics are stable.
