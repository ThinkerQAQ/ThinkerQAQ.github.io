## 1. Purpose

`CyclicBarrier` lets a fixed number of threads wait at a rendezvous point until all parties arrive.

When the final party arrives, the barrier opens and all participants continue.

## 2. Reusable Generations

Unlike a one-shot `CountDownLatch`, a `CyclicBarrier` resets for another generation after successful trip.

## 3. Barrier Action

An optional action can run when the barrier trips, before waiting threads are released to continue.

## 4. Failure

Timeout, interruption, or reset can break the current barrier generation. Other waiters receive `BrokenBarrierException` rather than waiting forever.

## 5. Use Case

Use a barrier when peer workers repeatedly execute phases such as:

```text
compute phase → rendezvous → next phase
```

Use a latch when one or more threads simply need to wait until N independent completions occur.
