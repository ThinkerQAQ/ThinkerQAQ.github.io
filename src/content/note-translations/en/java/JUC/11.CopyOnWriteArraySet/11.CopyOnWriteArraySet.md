## 1. What It Is

`CopyOnWriteArraySet` is a thread-safe `Set` intended for small, read-heavy collections that change infrequently.

It is implemented on top of `CopyOnWriteArrayList`: uniqueness is enforced when inserting, while successful writes publish a copied array snapshot.

## 2. Concurrency Model

Reads and iteration use an immutable published snapshot and normally do not contend with writers. Mutations are serialized and require copying the backing array.

This makes the structure attractive when traversal is much more frequent than mutation, but expensive when the set changes frequently.

## 3. Snapshot Iteration

An iterator sees the state that existed when the iterator was created. Later additions or removals are not visible to that iterator.

This avoids fail-fast iteration problems caused by concurrent modification, but it also means iteration is not a live view.

## 4. Complexity and Trade-offs

Because the backing representation is an array:

- membership checks are linear rather than hash-table lookups;
- writes require duplicate checking and, when successful, array copying;
- memory churn grows with set size and write frequency.

Use it for small listener/subscriber sets or similar read-mostly collections. For larger or write-heavy sets, a concurrent hash-based set is usually a better fit.
