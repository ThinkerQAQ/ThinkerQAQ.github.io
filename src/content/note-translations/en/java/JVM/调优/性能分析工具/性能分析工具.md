## 1. JVM-Level Tools

Useful first-party diagnostics include:

- `jcmd` for process/JVM commands and thread/heap/native-memory diagnostics;
- Java Flight Recorder (JFR) for low-overhead event recording;
- thread dumps for contention, deadlocks, and blocked stacks;
- heap dumps for retained-object analysis;
- GC logs for collector behavior.

Some older commands remain useful but should not be the only workflow when newer diagnostics provide richer data.

## 2. Profilers

CPU profilers show where execution time is spent; allocation profilers show object churn; heap analyzers show retained memory. Sampling is usually less intrusive than exhaustive instrumentation in production.

## 3. OS and Container Layer

Always correlate JVM results with process CPU/RSS, disk/network, page faults, cgroup throttling/limits, native-thread count, and dependency metrics.

## 4. Choose by Hypothesis

Do not capture every expensive artifact by default. A CPU incident calls for CPU/JFR/thread evidence; a retention incident calls for heap/live-set evidence; a native-memory incident needs process/native diagnostics. Select the lowest-risk tool that can confirm or reject the hypothesis.
