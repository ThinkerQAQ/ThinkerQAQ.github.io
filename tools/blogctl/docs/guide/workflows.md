# BlogCTL 使用流程

此文档区分现有可用功能与阶段性目标，避免把正在重构中的按钮说明成生产可用。

## 远端内容检测（已实现）

检测 → 选择平台 → 选择状态（全部、草稿、已发布）→ 查看远端标题、ID 与编辑/查看链接。

检测只读取远端列表，不会修改文章，也不需要选择本地文章。掘金列表目前以已发布文章为主，草稿需按已知 ID 检测。

## 当前文章更新（旧绑定契约，待迁移）

在当前版本更新页选择本地文章、平台并检测候选。已有创建/更新仍参考本地绑定记录；详见[目标架构](../architecture/unified-ui-and-console-20261010.md)。**暂不能保证「选择任意远端 ID 就直接更新」**，该能力要等新的显式任务目标接口交付。

## 计划中的三个动作（尚未完成）

- 创建：选择本地文章和平台，明确新建草稿或创建并发布，不查旧目标 ID。
- 更新：选择远端草稿或已发布文章，直接以本次任务目标 ID 更新原文；禁止将更新回退成创建。
- 发布：作为创建/更新流程内按钮，根据平台能力处理；任务快照用于重试和审计。

## 任务与索引（已实现）

- 任务中可查看平台状态、开始/结束时间、错误与重试入口。
- 索引提交独立于平台分发，不需要先完成创建/更新。

## 设置与数据

配置的唯一持久来源仍是 `blogctl.toml`；工具、分发策略和搜索引擎使用现有 Go Bridge API。设置的分类导航只改变呈现，不迁移文件。
