# 教程：第一次使用 BlogCTL 分发文章

先确认账号、检查远端文章，再决定是否创建草稿。这里把读取和写入分开操作。

## 1. 准备文章

按[博客引擎教程](../../../../../docs/zh-CN/tutorial/first-site.md)准备两个相邻的仓库：

```text
ThinkerQAQ.github.io/    引擎
blog-content/             文章原文
```

在内容仓库里准备一篇有真实 slug 的文章。

## 2. 连接 Bridge

完成[快速开始](../quick-start.md)，在工作台「设置」中选择 Engine Root、Content Root，并确保对应平台的浏览器账号已登录。

## 3. 查询远端

打开「检测」，选择平台，查看已发布文章及草稿。

再到「创建」选择本地文章，等待远端关联检测。存在同一篇文章时，应查看远端编辑链接，或者进入「更新」选择明确的目标；不要重复创建。

## 4. 在本地预览（可选）

在内容仓库目录执行：

```bash
blogctl sync --article YOUR_SLUG --platforms devto --dry-run
```

将 `YOUR_SLUG` 改为已有文章的 slug。此命令只编译预览，不向平台写入内容。

## 5. 明确执行创建或更新

检测成功且没有关联文章时，才在「创建」中执行「创建草稿」。已有文章使用「更新」，选择准确的远端 ID。

网络超时后先查看「任务」和「检测」，确认远端状态，不要直接重复提交。

## 6. 验证

在任务页查看平台结果、草稿 ID 和编辑链接。更多操作及平台差异见[工作流指南](../guide/workflows.md)，命令参数见 [CLI 参考](../reference/cli.md)。
