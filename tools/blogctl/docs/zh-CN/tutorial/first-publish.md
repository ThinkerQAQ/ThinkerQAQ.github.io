# 第一次创建平台草稿

这里以 DEV.to 为例。首次只选一篇文章、一个平台，便于检查结果。

## 准备文章与账号

先完成 [BlogCTL 安装](../quick-start.md)和 [Inkerio 内容教程](../../../../../docs/zh-CN/tutorial/first-site.md)，在「设置」填写引擎与内容路径。公开模板的原文 slug `sample-article` 同时有中英文版本。

在 DEV.to 分发设置中选择 `en`，并在运行扩展的浏览器配置中登录 DEV.to，或配置其 API Key。其他浏览器平台分别需要自己的登录会话。切换界面语言不会切换文章语言。

## 先检查本地编译

在内容仓库中执行，确保 `blogctl` 已加入 PATH：

```bash
blogctl sync --article sample-article --platforms devto --dry-run
```

该命令运行本地编译器，不需要已登录、正在运行的 Bridge。它可能安装缺失的 Node 依赖，并在本地保存工作区路径。退出码为 0 只表示编译成功，不代表账号、图片上传或发布成功；CLI 也不承诺生成 HTML 预览文件。

如果引擎不在内容仓库旁的默认目录，设置 `BLOGCTL_ENGINE_ROOT` 为引擎绝对路径。参见 [CLI 工作区定位](../reference/cli.md)。

## 创建草稿

1. 打开「创建」，选择 `sample-article` 和 DEV.to。
2. 账号可能已有文章时，手动点击「检测」。检测可选，不需要等待自动扫描。
3. 已有文章转到「更新」选择目标；需要新增时点击「创建草稿」。
4. 在「任务」检查平台结果，打开返回的编辑链接。

这一步会把示例写入真实平台账号，仅在确实需要这个草稿时执行。本地 dry-run 成功不会自动执行或授权远端写入。

## 检查结果

检查远端标题、语言、正文、封面、图片顺序和原文链接。任务中应包含远端 ID 与草稿结果。若图片插入等后续步骤失败，文章可能已经存在，应先查看记录的 ID，再决定是否重新创建。

更新草稿和公开发布分别执行。需要公开且平台支持时，才使用任务中的「发布草稿」。Medium 已发布文章先保存待发布版本，再由用户在 Medium 点击 **Save and publish**。平台差异见[完整工作流](../guide/workflows.md)。
