# BlogCTL v0.1.179

修复 Medium **Update 与 Create 采用不同文档替换语义**导致的正文格式残留问题。Medium 更新保持原草稿 ID，但将整篇标题与正文按新草稿编译结果完整重建。

## Medium 更新流程

- 之前：`Update` 保留旧标题段落，仅删除旧正文段落后插入新正文；旧段落样式可能被编辑器继承，与新建草稿的版式不一致。
- 现在：在读取并检查原草稿最新 revision、确认尚未发表后，按照逆序删除**所有**旧段落（包括标题），一次 revision-checked Delta 写入新标题及 Compiler 产生的所有正文段落。与 Create 保持一致，不复制旧文本/样式，也不会创建新的 Medium 草稿 ID。
- 浏览器图片继续使用已验证的真实编辑器插入方式；先回读验证完整替换后的纯文本段落，再逐张插入封面、表格和其他图片。
- 图片全部完成后，再执行严格的服务器端 GraphQL 回读，比对整篇标题、段落顺序和类型、正文、代码段、图片数量及 Medium CDN 元数据、所有行内 Markup（强调、行内代码、链接）类型与 UTF-16 位置。
- 如果远端内容或格式与 Compiler 不一致则报告失败；保留原草稿 ID 和可恢复任务，不会自动发布。
- 同时对无浏览器图片的旧版 Medium 更新路径采用相同完整文档替换及验证。
